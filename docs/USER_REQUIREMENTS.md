# 用户沟通需求与决策基线

本文由用户对话整理，不是完整聊天记录。示例脱敏；不上传真实凭据、保险库、私有主机或原始测试日志。已有代码不等于已验收。

## 产品与交付边界

- 保留原 TUI，GUI 是独立项目。控制端支持 Linux/macOS/Windows，第一版完整远端支持 Linux。
- 初始方案 Go + Fyne 2.8.0、指定 fyne-io/terminal 提交；因界面与终端问题转为 Wails + React + xterm.js。保留旧实现不表示旧版是当前主线。
- 单文件与便携持久配置。最初要求 Windows/macOS/Linux 各 amd64/arm64；后续明确先交付 macOS arm64，用户确认可用再构建其他平台。
- 不反复启动原生程序干扰用户设备。先调研上游、复审方案，再整批实现、验证、提交；后续测试/build/release 使用 GitHub workflow，不使用私有 runner。
- 旧 Linux ARM64 产物在离线麒麟服务器缺 libGL.so.1，用户明确不好改就不改、继续新版。当前不修旧产物，不要求服务器联网安装图形库。
- 单文件不等于无系统图形依赖；发布须说明运行条件。无桌面服务器 Web UI 只是建议，尚未授权实现。

## 双栏文件与拖放

- 三列：前两列分别选择本机/保存的 SSH 主机；第三列为任务和命令。
- 路径文本框可部分选中、编辑、有光标，回车访问；文件列表接近 ls -allt，含隐藏文件、权限、大小、修改时间，支持滚动。
- 拖到另一栏具体目录时放入该目录，空白区域才用当前路径；不能只支持已打开目录。
- 松开后复制/移动/取消；冲突时复制并覆盖/移动并覆盖/取消，目录合并。按钮足够大，不强迫使用修饰键。
- 操作使用端点解析的绝对路径，不能依赖终端 pwd。
- 文件区域中无需选中项目即可 Backspace 返回上层，不触发 edit-delete；输入框和终端保持原按键语义。
- d 删除、h SHA-256；底部有操作提示。拖动不能选中整页文字，悬浮目标和选中状态必须清晰。
- 默认/亮色/暗色安全组合键切换；避免同色背景文字。清晰字体与合理密度；第三列和配置弹窗不溢出。

## 每栏交互 Shell

- 真正持久的本地 PTY/SSH PTY，加载用户登录环境，不是一次性执行框。
- 主机未指定 Shell 时用登录默认 Shell；指定时遵守配置。
- Shell cd 后文件栏同步；鼠标或路径框改目录后 Shell 同步。
- 每次命令结束、删除和传输后刷新文件栏。提示符不能随机残留、重复、截断。

## 全局任务

- 全局同时一个任务，其余 Pending；复制/移动不能是不可见的后台操作。
- Running、Output、Pending、History 可见，支持取消；脱敏历史重启恢复，Pending 不恢复。
- 命令目标可选左栏/右栏/控制机，默认当前聚焦端点。
- 显示真实策略、方向、步骤与可获取的实际传输进度；未知进度不能伪造百分比，动画不能证明数据推进。
- 用户曾反馈 Pending/History 空白及没有状态；须真实 SSH 双任务闭环验证，不能以 mock 代替。

## Markdown 配置和保险库

- 严格使用单个无空行 Markdown，物理行号、不软换行；主机、私钥、SOCKS 三分区。
- SSH 主机与跳板暂不区分。多跳 FlySSH 串作为一个端点；--keys 逗号位置对应每跳，名字引用 vault 私钥而非文件。
- SOCKS 使用 user:pass@ip:port。示例保留用户结构，地址/口令脱敏：

```md
#主机
##主机名1
uhome:"EXAMPLE_PASSWORD_1"@192.0.2.10:41122,/bin/bash
##主机名2
uhome:"EXAMPLE_PASSWORD_2"@192.0.2.20:41122  uhome:"EXAMPLE_PASSWORD_3"@192.0.2.30:41122   uhome@192.0.2.40:41122 --keys ",,keyname1" ,/bin/zsh
##主机名3我不写shell你用登录默认的
demo:EXAMPLE_PASSWORD@192.0.2.50:22
#私钥
##keyname1
abc...
#socks池
##socksname1
user1:EXAMPLE_PROXY_PASSWORD@192.0.2.60:1080
```

- 每次启动输入主密码；首次确认密码、必填 hint。Argon2id + XChaCha20-Poly1305，hint 明文、正文加密、原子写入、仅当前用户访问。
- 程序旁已有 vault 优先，其次已有系统回退 vault；新安装先尝试程序旁创建，失败回退系统应用数据目录。当前工作目录与程序目录的便携语义须实机核对。
- 解锁后私钥可查看复制；密码默认遮罩。会话密码仅内存缓存，明确保存才持久化；退出/手动锁定重新锁定。
- 主机支持普通/root 用户、SSH/sudo 密码、私钥/口令、指纹、Shell、上次目录和默认路由。池支持管理、测试、排序、停用；日志/历史/预览脱敏。

## 传输策略

1. 预检绝对路径、冲突、空间、源 inode/size/mtime、架构、工具能力。machine-id/SSH 指纹/保存身份判同机，歧义按跨机。
2. 同机 cp/mv。跨机依次源普通用户推送、目标普通用户拉取、源提权推送、目标提权拉取。免密优先，其次会话缓存密码、保存密码。保护路径确认后 scoped sudo，不启动 sudo su Shell。
3. 各方向优先 rsync，再内置 SCP、认证加密流、tar+ncat；随机五个 20000–60999 端口、绑定具体接口。只有确认私网才自动明文，否则风险确认。
4. 直接失败后 SOCKS 池、SSH 跳板池；从实际发起端三次 TCP 探测取中位值，跳板真实握手；原计划要求重试相同方向/权限/方法组合。
5. 后续要求减少 SSH 暴露：成功跳板按主机对缓存，下次直接复用、失败再探测。当前仅成功会话和缓存关系进入自动候选，覆盖与行为待验收。
6. Hans 仅使用官方 v1.7.0 release 二进制，不复刻；一端 root/sudo server，另一端无 TUN userspace SOCKS client；随机网段/强口令、独立身份、固定指纹、require-v5、角色可反转；首次确认提权/ICMP/临时网络影响。
7. 最后控制机有界内存流中转，禁止落盘；目标同目录随机 partial、成功 fsync/rename，失败/取消清理。目录逐项传输，保留符号链接/模式/mtime，所有权仅提权模式保留。
8. 跨机移动逐文件 SHA-256，目录清单比对路径/类型/大小/哈希/链接目标；源未变且完整一致才删除，否则明确已复制但未移动。
9. Linux amd64/arm64/386/armv7 临时 agent/官方 Hans 嵌入，随机 0700 临时目录、SHA-256 校验；凭据经 SSH stdin 的版本化加密协议传递，不进入参数、环境或远端文件。取消关闭所有会话/监听/代理/Hans；只清理合法所有权标记且过期的资源。
10. 复用 FlySSH connector/transfer，保持 CLI 兼容；SSH 多跳/SOCKS、TOFU/指纹变化阻断、key/password/keyboard-interactive；SFTP 优先，禁用时安全 POSIX 回退。

## 验收口径

从真实成品入口和原始 API 契约开始，执行实际用户动作、核对文件及任务，再做回归。单测/mock/资源哈希/交叉编译不能替代整链可用。
首要闭环：真实 SSH 登录 → 浏览/终端同步 → 两笔传输 → 一笔运行一笔等待 → 完成/失败/取消 → 历史重启恢复。
后续验方向阻断、非 root sudo、代理/跳板/Hans、清理、零落盘与安全移动。交付源码、GPLv3、FlySSH MIT/Hans 许可、可复现 workflow、产物和 SHA256SUMS。
